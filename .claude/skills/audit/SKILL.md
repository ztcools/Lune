# 代码审计与深度优化

## 核心流程
逐模块审计 → 发现 bug/泄漏/耗时点 → 修复 → 验证 → 量化结果 → 下一轮。
反复此过程直到无新问题。每个修复都要实际验证，不靠理论判断。

## 审计维度
- Bug：逻辑错误、边界条件、空指针、并发竞态
- 内存泄漏：定时器/监听器未清理、对象引用未释放
- 性能：N+1 查询、不必要渲染、大计算在 computed 中
- 规范：硬编码、敏感信息泄露、僵尸代码
- 架构：核心链路合理性、模块耦合度

## 决策原则
- 优先选择对项目长期有利的方案，不因成本或复杂度逃避
- 允许大范围架构改动，只要对项目整体有利
- 用户方案不优时采用更优方案并说明理由
- 采用行业内成熟方案，不自造轮子

## 量化要求
验证必须产出可衡量结果：
- API：响应时间、返回行数、状态码
- 前端：控制台错误数、首屏渲染时间、内存快照
- DB：查询耗时、索引命中率、数据一致性

## 推进方式
每轮审计完成确认无误后推进 git commit，确保每步可回溯。
